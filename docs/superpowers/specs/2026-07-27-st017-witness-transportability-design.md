## 1. Research Question & Scope

Having established the formal necessity of the runtime governance kernel $\mathcal{K}_D = \{C_{\text{contract}}, C_{\text{uncertainty}}, C_{\text{temporal}}\}$ in ST-016, **ST-017** addresses the central transportability problem across heterogeneous runtime implementations:

> **Central Research Question (ST-017):**  
> Given a machine-certified witness artifact $W_{M_1}$ generated by reference runtime implementation $M_1$ (e.g. TypeScript), under what formal conditions $\sim$ is $W_{M_1}$ transportable to an independent implementation $M_2$ (e.g. Rust, Python) such that $W_{M_2}$ remains valid and certified under Lean 4?

$$\mathcal{M}_1 \sim \mathcal{M}_2 \implies \text{Witness}(\mathcal{M}_1) \vdash \text{Witness}(\mathcal{M}_2)$$

## 2. Theoretical Equivalence Conditions ($\sim$)

Two distinct runtime implementations $M_1$ and $M_2$ are declared **Kernel Equivalent ($M_1 \sim M_2$)** if and only if they satisfy four formal transportability axioms:

1. **Capability Geometry Preservation:**  
   $M_1$ and $M_2$ implement isomorphic capability kernel mappings:
   $$\text{Capabilities}(M_1) \cong \text{Capabilities}(M_2) = \{C_{\text{contract}}, C_{\text{uncertainty}}, C_{\text{temporal}}\}$$

2. **Policy Decision Monomorphism:**  
   For all observable state representations $R \in \mathcal{R}$, both runtimes produce identical discrete decisions under full composition:
   $$\forall R \in \mathcal{R}, \quad \pi_{M_1}(R) = \pi_{M_2}(R) = \pi^*(R)$$

3. **Semantic Contract Invariance:**  
   Contract evaluation functions in both runtimes share identical truth values for domain safety assertions.

4. **Witness Schema Compatibility:**  
   Both runtimes emit structured `WitnessArtifact` representations adhering to the normative Lean 4 3-layer certification bridge (`WitnessConsistentWithRuntime`).
