\section{Machine-Certified Lean 4 Formalization}

The Lean 4 development in \texttt{takt-formal} provides the algebraic framework
within which the ST-016 runtime model is defined and analyzed.

\subsection{Core Definitions (\texttt{RuntimeSufficiency.lean})}

The key definitions, verbatim from the Lean source:

\begin{small}
\begin{verbatim}
inductive RuntimeCapability
  | contract | uncertainty | temporal

structure Runtime (S : Type) (D : Type) where
  capabilities : Set RuntimeCapability
  policy       : S -> D

def NecessaryCapability (C : RuntimeCapability) (M : Runtime S D) : Prop :=
  Exists r, M.policy r != (removeCapability M C).policy r

def Sufficient (M : Runtime S D) (pi_star : S -> D) : Prop :=
  forall r, M.policy r = pi_star r

def MinimalRuntime (M : Runtime S D) (pi_star : S -> D) : Prop :=
  Sufficient M pi_star /\ Irreducible M
\end{verbatim}
\end{small}

As a definitional consequence, any \texttt{MinimalRuntime} has all its capabilities
necessary by construction (\texttt{Irreducible} is the second conjunct).
The non-trivial lemma \texttt{necessary\_implies\_non\_preservation} proves that
a necessary capability, when removed, strictly breaks \texttt{PreservesDecision}.

\subsection{Formal Witness Validation Schema (\texttt{RuntimeWitness.lean})}

A \texttt{WitnessArtifact} is a record encoding a single observed policy
divergence under capability ablation. Table~\ref{tab:witness-example} shows
a concrete witness for $C_{\text{temporal}}$ drawn from EXP-004.

\begin{table}[htbp]
\caption{Concrete \texttt{WitnessArtifact} for $C_{\text{temporal}}$ (EXP-004, ablation 3)}
\label{tab:witness-example}
\centering\small
\begin{tabular}{ll}
\toprule
\textbf{Field} & \textbf{Value} \\
\midrule
\texttt{cap}              & \texttt{RuntimeCapability.temporal} \\
\texttt{representation}   & \texttt{R2} (unsafe prefix, same terminal state) \\
\texttt{fullDecision}     & \texttt{INTERVENE} \\
\texttt{reducedDecision}  & \texttt{MONITOR} \\
\texttt{divergence}       & \texttt{true} ($\pi_M(R^2) \neq \pi_{M\setminus\{C_\text{temporal}\}}(R^2)$) \\
\bottomrule
\end{tabular}
\end{table}

The construction and verification pipeline is:
\[
\underbrace{\text{EXP-004 trace}}_{\text{TypeScript}}
\xrightarrow{\text{manual encoding}}
\underbrace{\texttt{WitnessArtifact}}_{\text{Lean record}}
\xrightarrow{\texttt{WitnessConsistentWithRuntime}}
\underbrace{\texttt{NecessaryCapability}}_{\text{Lean theorem}}
\]
The first arrow is manual: a human observes the TypeScript divergence and encodes
it into a \texttt{WitnessArtifact} record. The second arrow is machine-checked:
Lean verifies that if the record is consistent with the formal runtime model,
then the corresponding capability is formally necessary within that model.
